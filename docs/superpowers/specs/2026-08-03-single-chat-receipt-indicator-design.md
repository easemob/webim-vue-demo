# 单聊与群聊回执对勾展示设计

## 目标

让单聊与群聊发送方的消息状态在同一位置按真实 SDK 5.0 回执递进展示，避免将送达和已读状态重复显示为上下两组图标。

## 范围与约束

- 仅修改单聊与群聊发送方消息的送达/已读视觉状态。
- 单聊直接读取 SDK 5.0 原始 `delivered` 与 `isPeerRead`；群聊直接读取原始 `delivered` 与 `groupReadCount`。
- 不改变回执发送、接收、Store 写入或群聊已读人数逻辑。
- 不引入 SDK 4.0 字段、映射、兼容或本地推断。

## 展示契约

| 会话类型 | SDK 5.0 原始状态 | 发送方展示 | 说明 |
| --- | --- | --- | --- |
| 单聊 | `delivered === true` 且 `isPeerRead !== true` | 绿色 `✓` | 对方已送达，尚未收到真实已读回执。 |
| 单聊 | `isPeerRead === true` | 绿色 `✓✓` | 对方已读；此状态覆盖单独的送达勾。 |
| 群聊 | `delivered === true` 且 `groupReadCount` 不大于 `0` 或未下发 | 绿色 `✓` | 消息已送达，尚无真实群已读人数。 |
| 群聊 | `groupReadCount > 0` | 绿色 `✓✓` | 至少一名群成员已读；此状态覆盖单独的送达勾，并保留原始已读人数。 |
| 单聊或群聊 | 对应字段均不满足 | 不展示 | SDK 没有给出送达/已读事实。 |

接收方不展示对方消息的回执图标。群聊不读取 `isPeerRead`，已读人数仍严格直接展示真实 `groupReadCount`。

## 验证

扩展现有 Node 合同测试，先证明当前双节点模板不符合“单一递进状态”契约，再以最小模板/CSS 改动使其通过；随后执行相关回执合同测试、格式检查和生产构建。
